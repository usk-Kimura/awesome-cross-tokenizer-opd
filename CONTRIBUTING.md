# Contributing

Thank you for helping keep this survey accurate. Corrections are as valuable as
new-paper suggestions.

## Before proposing a core paper

Please verify all of the following in the public full text:

- the training trajectory or visited state is generated by the student/current
  policy;
- teacher and student use explicitly different tokenizers or vocabularies;
- the paper describes how a teacher signal crosses that mismatch; and
- at least one mismatched teacher–student pair is actually trained and reported.

Cross-family model names, a sentence about tokenizer mismatch in the
introduction, or separate claims that a framework supports OPD and
cross-tokenizer KD are not sufficient on their own.

## What to include

For an addition or correction, provide:

1. the primary paper/venue URL and exact public version checked;
2. section, equation, table, appendix, or public-code permalink for each claim;
3. teacher and student names in **Teacher → Student** order;
4. trajectory source, comparison interface, feedback coverage, teacher access,
   and probability/mass semantics;
5. official code/project URL and its status; and
6. any ambiguity, missing implementation detail, or mismatch between paper and
   code.

Do not copy abstracts or long passages. Write an original, compact summary and
link to the source.

## Pull requests

- Update the English `README.md`; keep `README_ja.md`, `README_zh.md`, and
  `README_ko.md` aligned when the taxonomy or a central conclusion changes.
- Add or revise the corresponding record in `data/papers.yml`.
- Add a BibTeX entry to `references.bib` for a new paper.
- Preserve the distinction among core methods, evidence-caveat rows, boundary
  applications, frameworks/resources, and off-policy enabling work.
- Set `last_verified` only to the date on which links and claims were checked.
- Preserve each work's full-text `last_verified` when only rechecking its version
  or code link; use `metadata_last_verified` and `code_last_checked` for those
  checks. The top-level date identifies the latest survey refresh.
- Applied pipelines meeting the core criteria belong in `core_application`;
  separate their complete-pipeline results from isolated bridge evaluations.
  Fixed-reference KD additions belong in `adjacent_off_policy`.

Use the issue forms if you would rather submit evidence without editing the
repository.

## Research catalogue

The GitHub Pages catalogue is built from `data/papers.yml` and `references.bib`.
Keep the short summaries in `web/summaries.json` aligned in all four languages;
write the author's contribution or finding separately in `web/claims.json`.
Claims appear directly below titles in both the static HTML and interactive
catalogue. Paraphrase the primary source, attribute reported results, and keep
implementation concerns in the method notes rather than in the author's claim.
The detailed source metadata remains in English. Code availability tables in
the READMEs are generated, so update the data rather than editing those tables.

```bash
python -m pip install -r requirements-site.txt
python scripts/sync_code_tables.py
python -m unittest discover -s tests -v
python scripts/build_site.py
python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

Open `http://127.0.0.1:8765/` for a local preview. Optional browser checks use
Playwright: `python scripts/check_browser.py`. The checks cover multilingual
search, filters, comparison, citation downloads, shared URLs, mobile layouts,
and reading without JavaScript. The Pages workflow validates and publishes the
catalogue when changes reach `main`; pull requests only build and validate.

The build includes localized search/social metadata, reciprocal language links,
and JSON-LD describing the catalogue and its external papers. `sitemap.xml`
uses canonical language URLs; search/filter URLs share those canonical pages.
The project's `robots.txt` is provided as a reference, but crawlers use the
host-root robots file on GitHub Pages. Search Console ownership and submission
are managed separately from this build.

The social preview is `web/social-card.png` (1200 × 630), rendered from
`web/social-card.svg`. Keep it consistent with the site branding. Japanese
claims and explanations should use characters covered by the bundled font;
see `web/fonts/README.md` when extending its subset.

## Evidence and tone

“Verified” means checked against public primary material, not experimentally
reproduced. Attribute numerical or exactness claims to the paper, state negative
findings narrowly (for example, “no official code found as of DATE”), and make
uncertainty visible instead of filling gaps by inference.

By contributing, you agree that your changes to this survey's metadata and
original summaries are released under [CC0 1.0](LICENSE). Linked papers, code,
and third-party materials retain their own licenses.
